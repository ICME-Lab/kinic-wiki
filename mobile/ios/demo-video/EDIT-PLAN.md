# 新機能デモの編集計画

2026-10-07。対象は共有 Work items とホーム画面ウィジェット。
既存の横長版・画面録画を連結した縦長版を改善するための計画。
本書の秒数・倍率・演出値は提案であり、公式の推奨値ではない。

## 仕上がり

iPhoneと同じ縦横比、1206 × 2622、30fps、約25秒。
画面が主役。操作前の全体像、操作中の寄り、結果を読む静止にリズムをつける。
黒いアプリ画面とピンクのアクセントに合わせる。端末枠、横の説明欄、長いロゴ導入を設けない。
小さな字幕は「Shared Work items」「Home Screen widget」程度に絞る。

## 調査から使う手法

- Screen Studioは編集時にズームの範囲・倍率・長さを指定できる。
  [公式ズーム編集](https://screen.studio/guide/adding-editing-zooms)
- 入力区間だけを速める編集が公式に用意されている。今回は自動検出に頼らず素材上で区間を指定する。
  [公式入力区間の速度調整](https://screen.studio/guide/speed-up-typing-segments)
- iPhone/iPad録画では指のタップを取得できず、自動ズームが非対応。
  [公式iOS録画](https://screen.studio/guide/recording-iphone-ipad)
- 既存MP4をインポートしてズーム等を付けられるが、録画時のマウス情報は復元されない。
  [公式既存動画の取り込み](https://screen.studio/guide/creating-project-from-existing-video)
- Remotionのinterpolateとspringで画面の位置・倍率・演出の時間変化を制御できる。
  [interpolate](https://www.remotion.dev/docs/interpolate)、[spring](https://www.remotion.dev/docs/spring)
- Remotionにはモーションブラーもある。まずは文字の鮮明さを保つズームを作り、
  必要なら移動中だけ試す。
  [motion blur](https://www.remotion.dev/docs/motion-blur)

## 絵コンテ案

| 時間 | 見せる内容 | 編集・演出 |
| --- | --- | --- |
| 0–2秒 | 内容が入ったウィジェット | ウィジェットへ寄った画から全体へ戻り、新機能の結果を先に見せる |
| 2–8秒 | Work item作成 | New itemに小さなタップリング。タイトル入力へ1.2–1.45倍の寄り。タイトルを約0.8秒で入力。本文は途中を省略し、完成した内容を見せてSaveへ移動 |
| 8–13秒 | コメント | コメント欄へ寄る。約0.8–1秒で文が現れる入力演出。送信タップのリングと短い音。投稿されたコメントを1–1.5秒読ませる |
| 13–17秒 | 完了 | Closeボタン→Closed状態へ視点を移す。実際の状態変更にピンクの細いハイライトを重ね、Closed一覧で結果を確認 |
| 17–23秒 | ホーム画面ウィジェット | ホーム画面へ切り替え、ウィジェットへ約2倍の寄り。タップで項目を開く実映像を追加し、入口としての便利さを見せる |
| 23–25秒 | 開いた項目 | 内容を読み取れる位置で止め、小さなKinicWiki表記で終える |

作成・コメント・完了は同じ「Ship the next idea」を使う。
ウィジェットには残っている未完了の「Plan the next research session」を表示する。
完了した項目が未完了一覧に残るような編集にはしない。

## 演出仕様

- ズーム：操作対象の矩形を決め、周囲に余白を残して倍率と中心を計算。
  約0.35–0.5秒で移動。弱い減速で止め、文字を読む間は動かさない。
  ボタン・入力文がフレームから切れないことを倍率より優先する。
- タップ：操作した位置に小さなピンクの円が0.2–0.3秒で広がり消える。
  座標と時刻を手動で記録。画面のズームと同じ変換をかけて位置ずれを防ぐ。
- 入力：既存入力を区間ごとに加速する。必要な箇所では実画面の入力欄に合わせた
  テキストレイヤーでタイプ表示を再構成する。元の文字はマスクし、二重表示を防ぐ。
  単語単位の軽い出現、細いカーソル、入力欄の短い縁の発光を候補とする。
  実際の保存後の画面につなぐ。入力完了後には読む間を残す。
- 時間：キーボードの出入り、待機、戻る操作をカット。全区間の一律倍速は避ける。
- 結果：投稿やClosedへの変化を1–1.5秒保持。演出は一度に一つの対象へ付ける。
- 音：控えめなBGMに、送信・完了・主要なカットの短い効果音を合わせる。
  文字ごとの大きなタイプ音は付けない。無音でも意味が伝わる画を作る。
- UIの機能・保存結果は実画面に合わせる。タイミング、入力過程、カメラ、ハイライトは
  デモ向けに再構成する。現素材はローカルデモデータのため、別ユーザーの投稿や
  他端末へのリアルタイム同期を実証する映像として扱わない。

## 制作順序

1. 元映像からNew item、入力開始・終了、Save、送信、Closeの正確なフレームと座標を採る。
2. 既存Remotionに縦長の編集用Compositionを追加。カット、ズーム、タップ、入力を
   データで管理し、映像と演出を同じタイムラインで再生する。
3. 最初に作成シーンだけの約6秒の試作を作り、完成解像度とスマホ程度の表示サイズで確認。
4. コメントと完了へ演出を展開。読む時間を確保して約25秒に収める。
5. タスク専用Simulatorでウィジェット→項目を開く場面を追加撮影。
   現在のウィジェット素材は静止画なので、この動作は新しい映像が必要。
6. ウィジェットの寄りと遷移を仕上げ、音を最後に調整。全編を書き出す。

追加のソフト購入は不要。既存のRemotionで再現性のある編集ができる。
Screen Studioを手動編集の道具として使う場合も同じ絵コンテを適用できるが、
今回の入力レイヤーと座標付きタップ演出はRemotionで実装する方針。

## 完成の確認条件

- スマホ程度の表示でもタイトル・コメント・Closed状態が読める。
- 指示なしでタップ位置と結果が追える。リングとUIの位置がずれない。
- 入力中の文字が二重にならず、キーボードや字幕が主題を隠さない。
- ズームの切れ目で画が飛ばず、状態・項目・コメントの順序が一致する。
- ウィジェットの場面では中身が読み取れ、タップ後に対応する項目が開く。
- 保存結果を読む間を残し、不要な待機を削る。無音でも新機能の流れが伝わる。
